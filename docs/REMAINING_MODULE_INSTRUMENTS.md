# Remaining operational modules: first instrument implementation

Under PR #37, Core supplies decisions and proposals; the modules provide instruments and objective checks. This change does not alter training, the default module list, the production activation mechanism or PR #39's BPE adapter.

| Module | Added instrument | Remaining integration and qualification |
| --- | --- | --- |
| Business | Explicit opt-in development controller module with owner-defined scenario parameters, proposal-driven planning and independent integer-cent operating-result arithmetic | Sourced due diligence, realistic market constraints, multi-period accounting, acquisition analysis and independent actual commercial outcomes |
| Conversation | Exchange history append instrument preserving exact question and answer | Controller-managed multi-turn history and retrieval, memory budget and sustained real Core examination |
| Authorship | Ordered section assembly and DOCX export using Times New Roman 12-point double spacing | Controller-managed long manuscript state, reference retrieval, editorial and mathematical review, completed long-form original work |
| Engineering | Exact source fingerprint and compile evidence | Controller-managed workspace changes, isolated execution, independent functional tests, reproducible builds |
| Research | Verify cited observations and retain inference without substituting it | Controller-managed experimental instruments, independent substantive evaluation, counterfactual tests |

The four work-product functions are standalone instruments, not automatically invoked by the existing modules in this change. Business uses the existing scoped controller and is registered explicitly through the development factory my_own_ai.business_module:build_module. Its scenario completion is arithmetic evidence, not a demonstrated commercial outcome. It does not select the proposal or authorize external commitments.

No new doctrine, external reasoning model, live financial permissions, or training changes. The owner retains the existing approval requirements. Test fixtures verify mechanics rather than actual Core competence. Follow-on changes must integrate these instruments, support the original BPE runtime, and evaluate actual qualified neural outputs before production activation.
